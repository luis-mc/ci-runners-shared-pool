# Changes from v4

- C1: component 65 (stepper) is removed: Help is rebuilt as layout G (the job path on top, every question card in one grid, no wizard, no step lock; D58 replaces D55), so nothing uses it. The job path sets `aria-pressed` only when a part is lit, and the `primary` guard leaves the boxes of the job path out like tabs and chips (components.md 64, 65, `packages/ui` Help, `e2e/tests/web-console/ux-guards.ts`; LOOK47).
- C2: UX-10 says the sections of every page are 32 px (`--ds-space-6`) apart and a search, filter or step bar above a pane leaves the same gap, so a focus ring never covers a pane title. The shared parts hold it: the page, a stack that holds panes, the search table and the wizard use the section gap; the DOM layout rules `section-gap` and `title-clear` (`scripts/design/dom-layout.ts`, run by `e2e/tests/web-console/ux-routes.spec.ts` at 360, 393 and 1300 px) check it (ux-rules.md UX-10, packages/ui components.css; LOOK46).
- C3: content.md gains the Run follow-up words: *Started next*, the status *follow-up running* beside a run's own result, the hover text of the Result column, and the Timeline row and note for a follow-up's runner wait (content.md; CIX24, owner decision D27). No rule, token or component changed.
- C4: Native update window words: `Waiting for another installer` with `{name} is installing. Windows installs one program at a time; this update starts when it finishes.` (`Another program` without a name), and `Restarting the service` shows only once the installer has finished (content.md Native update window words and the Update page live line; TRAY11).
- C5: new rule UX-78 and component 68 (Date and time): a date and time stays on one line everywhere, shown with the shared `DateTime` part; the DOM layout rule `time-one-line` (`scripts/design/dom-layout.ts`) checks it at 360, 393 and 1300 px. The Export of a list sits in its toolbar, never over the rows (ux-rules.md UX-78, components.md 68, `packages/ui` DateTime, `e2e/tests/design-layout.spec.ts`; LOOK49).
- C6: fields in a row (component 14, 43) top-align; each field takes one grid row for its name, box, help and mistake, so a long name or help never moves a box (components.md 14, `packages/ui` components.css `.ds-field-grid`; LOOK49).
- C7: audit log words: the column head On and the plain Details text (content.md, Audit log words; LOOK49).
- C8: component 69 (Help question card) is new: a card with a *Box N: Name* badge that links to and lights its box of the job path, and a small picture from the shared pictures `PictureShared`, `PictureRun`, `PictureLabels`, `PictureElsewhere`, `PictureQueue`, `PictureSlots`, `PictureBudget`, `PictureRunnerType`, `PictureTray`, `PictureDoctor`; `CardGrid columns={4}` gives 4, 2 and 1 columns. Component 64 shows a live example under a box's name (components.md 64, 68, content.md Help words, `packages/ui` Help, HelpPictures, Card, components.css; LOOK48).
- C9: "Runner kind" is a retired word; the field that says persistent or ephemeral is **Runner type**, or **Type** where the page or wizard step is already about runners (a field on a runner page, the Add runners step). "System" stays for Linux or Windows. The follow guard scans for "Runner kind" as UI text; the bare word "Kind" stays allowed for other fields such as a notification channel or an image (content.md Retired words; CORE-3, CORE-5, UX-58, UX-61; LOOK50).
