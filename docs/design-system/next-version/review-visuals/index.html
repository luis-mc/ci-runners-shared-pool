ux-rules.md

UX rules

Core UX Principles

> Binding. These seven principles are not starter items. Do not delete or weaken them. Every UX rule below serves one of them.

Every screen of every app must be:

  • CORE-1 Consistent: the same thing looks and behaves the same everywhere (same wizard, buttons and words for the same action).
  • CORE-2 Built from reused components (shared UI package; no one-off variants; the duplication check stays green).
  • CORE-3 Clear: one headline says where you are; plain words; never raw file paths or codes as the main text.
  • CORE-4 User-friendly and intuitive: an action takes exactly what you see (never hidden items); no redundant buttons; nothing to decode.
  • CORE-5 Assertive: one primary action per screen, labelled by what it does ("Import 8 files"), with its reason; say what happened and what comes next.
  • CORE-6 Guided: a step-by-step path drawn as the wizard (a step bar on top, only the current step below it, Back and the one primary action at the bottom; done steps can be looked back at, later steps are greyed and not pressable); no dead ends.
  • CORE-7 Boxed sections are consistent and aligned: boxed sections (cards) present their content the same way (title, fonts, the layout of their facts and their action); boxes that sit next to each other share one width and one height, in a grid that makes the best use of the horizontal and vertical space on desktop and phone (as many columns as fit, never one narrow column with empty space beside it), with clear, balanced spacing between them so no box or its shadow touches or overlaps the next; a card may span 2 columns only when its row stays full.

A UI change that fails any of these is not done. Every UI brief and PR body checks itself against them and cites the CORE IDs it checked.

  • Used for: one overlay component with three forms, chosen by screen width and by purpose (UX-43). On a small screen it is a bottom sheet. Forms

FormWhenBehaviour
Bottom sheetBelow --ds-bp-sm (600px), for both purposesSlides up from the bottom edge. Full width. The page behind is dimmed.
DialogAt --ds-bp-sm and wider, when it changes data (a question, a form, a confirm)Centred. The page behind is dimmed. It is modal.
PopoverAt --ds-bp-sm and wider, when it only changes the view (a filter, a sort, a display choice)Anchored to its opener. No dimming. It closes on a click outside.

A small-screen popover is a bottom sheet, so a thumb always reaches it. One component renders all three; a screen never builds its own overlay (UX-2).

Anatomy

1. Handle. A short bar at the top edge of a bottom sheet that can be dragged down to close it. A dialog and a popover have none. A sheet without a drag has none either. The handle is decoration: the close button is the real control (UX-17). 2. Header. The title (a section title, one line) and a close button (at least --ds-target-min square, labelled "Close"). The title is what the overlay is named by. 3. Body. The content. It is the only part that scrolls. The header and footer stay in view. 4. Footer. The one primary action on the right, and Cancel on the left (UX-4, UX-24). A view-only popover has no footer: its choices apply at once, and the close button ends it.

The body scrolls when the content is taller than the space. The overlay never grows past the screen (UX-16).

Tokens

  • Surface: --ds-color-surface. Dimmed page: a --ds-color-text layer at a low opacity. Edge: --ds-color-divider and --ds-hairline.
  • Corners: --ds-radius-3. Shadow: --ds-shadow-3.
  • Gaps: --ds-space-4 inside the header, body and footer; --ds-space-3 between footer buttons.
  • Z-order: --ds-z-overlay for the dimmed page, --ds-z-dialog for the overlay, --ds-z-menu for a popover.
  • Motion: --ds-duration-slow for a sheet, --ds-duration-base for a dialog or popover, with --ds-ease.
  • Focus ring: --ds-focus-width, --ds-focus-offset, --ds-color-focus.

Behaviour

  • Focus trap. While a modal form is open, Tab and Shift+Tab move only between controls inside it. The page behind is inert.
  • Escape closes. Escape closes every form and counts as Cancel. A form with unsaved input asks first.
  • Focus in and out. On open, focus goes to the safe choice: the first field of a form, or Cancel in a question. On close, focus returns to the opener (UX-35). If the opener is gone, focus goes to the page's heading.
  • Scroll lock. While a modal form is open, the page behind does not scroll, and it does not jump when the lock starts or ends. A popover does not lock.
  • Outside click. A click on the dimmed page closes a popover. It closes a sheet or dialog only when nothing is entered.
  • Motion. A sheet slides up and a dialog fades in, both short (UX-36). Under prefers-reduced-motion the overlay appears and goes at once (UX-17).

Accessibility

  • The overlay has role="dialog". A question that needs an answer before anything else uses role="alertdialog".
  • A modal form has aria-modal="true". A popover is not modal and does not set it.
  • It is labelled by its title (aria-labelledby). A line of explanation is its description (aria-describedby).
  • The close button has a text name. The handle is hidden from assistive technology.
  • Contrast and the focus ring follow UX-17 in every theme.

When not to use it

  • To tell the user something: use a message or the banner (component 18).
  • For a guided flow of steps: use a wizard (component 4).
  • For content the page needs to work: put it on the page (UX-14). An overlay is for a short, focused task.
  • For a long form or a task of several steps: use a page.
  • For a list of actions at the end of a card: use buttons in the card (UX-37).
  • For one more overlay on top of an overlay: change the first one instead. Never stack them.

62. Cell full-text

  • Used for: a table cell, card title or list line whose text may be longer than its box. It is the way UX-72 (D14, D15) makes the full text reachable.
  • Anatomy: by default the text is whole: it wraps and a long path, id or word with no space breaks anywhere to fit. Only where the box has a line limit (a name at two lines, ClampText, component 56) or a very narrow column does the text end in an ellipsis. A cell that ends in an ellipsis is a *cut cell*, and a cut cell always carries the full text three ways: a tooltip with the whole text on mouse hover and on keyboard focus (the cell is focusable with tabindex="0" only when it is cut); a tap on touch expands the row to show the cell whole, and a second tap folds it; and the text itself for a screen reader (the whole text is in the DOM, the cut is drawn by the style). A cell that is not cut has none of these. Rows may differ in height.
  • States: *whole* (not cut); *cut* (ellipsis, a dotted underline, focusable); *tooltip shown* (hover or focus; Escape closes it, UX-57); *expanded* (touch; the row grows, the cell shows whole text, aria-expanded is true); *folded*.   • Tokens: --ds-color-surface and --ds-color-border for the tooltip, --ds-color-text, --ds-space-2, --ds-radius-2, --ds-z-menu for the tooltip layer, --ds-color-focus. No new token.

A tooltip is not the only way: on touch the tap is, and the row's detail page always shows the text whole.
  • Phone (360, 393 px): no hover exists, so the tap is the way; the expanded row pushes the rows below it down, never over them; the tap target is the whole cell, at least --ds-target-min high. A long path or id breaks anywhere and needs no tap while it fits in two lines.

How themes work

  • The dark values are the default. The console looks like a terminal. Six named colour themes change the colour values (see Colour themes).
  • The light values apply under @media (prefers-color-scheme: light) and under [data-theme=light]. The attribute wins over the system setting.
  • The tables list the light value first and the dark value second.
  • A token has the same name in every theme. Only its value changes.
  • Text and its background meet WCAG 2.2 AA contrast in every theme (UX-17): at least 4.5:1 for text, 3:1 for large text and for borders of controls. WCAG 2.2 AA stays the rule. A project may choose 7:1 for body text in the dark theme.

@media (prefers-color-scheme: light) {
  :root:not([data-theme=dark]) { --ds-color-page: #f3f6f4; }
}
[data-theme=light] { --ds-color-page: #f3f6f4; }

Colour themes

Owner decisions LOOK D1 and D2 (2026-11-15): the console looks like TUI panes, and all six palettes are themes the user picks in Settings (UX-60). A theme is a set of token values and nothing else (UX-55).

  • Six themes: phosphor, tokyo-night, catppuccin, gruvbox, solarized, nord. Each has a dark and a light value set.
  • Default for a new install: phosphor, in dark mode (owner decision LOOK D11). A page with no theme set is Phosphor; the tables of the first colour section above describe the starter values and are replaced by the Phosphor values below. The light themes keep exactly the look page values (D12).
  • A sample of a theme: an element that carries both data-theme-name and data-theme (the theme preview) keeps its own mode inside a page in any theme or mode.
  • How a theme is applied: the attribute data-theme-name=<id> on the page root picks the theme. The mode stays as written under "How themes work": [data-theme=light|dark] or the system setting. The two attributes are independent. The attribute may also sit on one element (the swatch row in Settings); the tokens then apply to that element and what is inside it.
  • New token: --ds-color-selection, the fill of the row under the cursor. A selected row is drawn in reverse video: --ds-color-primary fill with --ds-color-on-primary text.
  • Radius: --ds-radius-1, --ds-radius-2 and --ds-radius-3 come from the theme: 0 for Phosphor, Tokyo Night, Gruvbox and Solarized, 8px for Catppuccin, 6px for Nord. --ds-radius-round does not change.
  • Focus effects: --ds-glow-focus and --ds-scanline-focus follow each theme's primary colour (dark: ring plus glow, scanline at 6%; light: ring only, no scanline).
  • Derived values (the same rule for every theme, so nothing is hand-picked): --ds-color-divider is the border mixed 30% into the surface. Each tone's tint (--ds-color-X-tint, and -bg with the same value) is the tone mixed 14% (dark) or 12% (light) into the surface, thinner when the tone would not read 4.5:1 on it. --ds-color-on-X (text on a solid tone) is on-primary, else white, else black, the first that reads 4.5:1. --ds-color-on-X-tint is the tone itself. --ds-color-focus is the primary.
  • Contrast: in every theme and mode, text pairs are at least 4.5:1 (text, muted text, inactive text and every tone on the page, the surface and the selection fill; on-primary on primary; every on- pair) and borders at least 3:1 on the page and the surface (UX-17). scripts/design/themes.test.ts proves it, and proves that every theme defines every token.
